# Spektrafilm OFX in Milan Pro

Spektrafilm (https://github.com/chaert-s/spektrafilm-ofx) is a film-emulation OFX plug-in written for DaVinci Resolve and Nuke. This page compares what its source asks of a host with what Milan Pro's OFX host provides (Milan Pro 0.6, `milan-plugin-host.exe`).

**Status: expected to work, not verified with the real binary.** The comparison below comes from reading Spektrafilm's source (`src/SpektraFilmPlugin.cpp`, `src/SpektraParameters.h`, `src/SpektraVulkanRenderer.cpp`, `CMakeLists.txt` on the main branch, November 2026). Milan Pro's host was tested with its own test plug-in (`tools/ofx-test-plugin`, which exercises the same host calls: push buttons, `paramSetValue` from the plug-in, `kOfxParamPropSecret` / `Enabled` changed at run time, `propReset` + `propSetStringN` on choice options, `paramEditBegin/End`, messages with printf arguments, an error from the render action), not with Spektrafilm's release binaries, which were neither downloaded nor run while building this.

## What Spektrafilm needs, and what Milan Pro provides

| Spektrafilm needs | Milan Pro | Notes |
|---|---|---|
| `OfxSetHost` (OFX 1.5 export), `OfxGetNumberOfPlugins` (1 per DLL: `org.spektrafilm`, `org.spektrafilm.flow`, `org.spektrafilm.dev`), `OfxGetPlugin` | Yes | `OfxSetHost` is called when exported, before the plug-ins are listed. |
| Suites: Image Effect v1, Property v1, Parameter v1 (its load fails without them), Message v1 (optional) | Yes | Also offered: Memory, MultiThread, Progress v1/v2, TimeLine, Message v2, a stub Interact v1. |
| Context: Filter only | Yes | Filter, General, Transition and Generator are run. |
| Pixel depths: 16-bit half and 32-bit float (no 8-bit) | Float | Milan Pro hands it 32-bit float RGBA (it prefers float; half is also available). |
| Components: RGBA on Source and Output | Yes | Premultiplied, bottom row first, as OFX defines. |
| Tiles off, temporal access off, multiple clip depths off | Yes | Milan Pro always gives the whole frame at one depth. `clipGetImage` at another time returns the current frame. |
| Host name checks (Resolve, Nuke) | None found | Its source does not check the host's name. |
| GPU render suites (CUDA, OpenCL, Metal, OpenGL) | Not provided | Not needed on Windows: Spektrafilm takes the host's CPU float buffers and runs its own Vulkan 1.1 compute pipeline inside the plug-in. Its Metal path is macOS-only and off by default. |
| A Vulkan 1.1 device with a compute queue (`vkCreateInstance` with no extensions, `vkEnumeratePhysicalDevices`; no window or surface) | Yes, verified | The plug-in host, started as Milan Pro starts it (Job Object, no console, no window), made a Vulkan 1.1 instance and found "AMD Radeon Graphics (compute queue)" on the development PC (`the_host_can_make_a_vulkan_device`). The Job Object sets no UI or desktop limits. Spektrafilm has no CPU fallback: without Vulkan its render fails ("No Vulkan physical device is available." and similar) and Milan Pro bypasses it, showing that text verbatim in the FX window and the Plug-In Manager. |
| Shader files from its bundle (`Contents\Resources\shaders\*.spv`, found from the DLL's own module path via `GetModuleFileNameW`, or `SPEKTRAFILM_RESOURCE_DIR`) | Yes | The bundle is loaded in place from `C:\Program Files\Common Files\OFX\Plugins`. |
| OFX 1.5 colour management (`kOfxImageEffectPropColourManagementStyle` = Core) | Not provided | Milan Pro does not implement OFX colour management; Spektrafilm reads nothing back and fetches no colour suite. Its own Input and Output colour space parameters decide (see below). |
| Parameters: Group, Choice, Double, Integer, Boolean, RGB, Double2D, Double3D, String, PushButton | All | Pages and groups lay out the FX window as the plug-in defines them (groups open and close); parameters it marks `kOfxParamPropSecret` are hidden and `kOfxParamPropEnabled` 0 are greyed, as it changes them at run time (`syncConditionalParamVisibility`: the HDR, RCM, grain, enlarger and scanner sets); labels and choice options follow run-time changes (the preset list `presetSelection` is refilled with `propReset` + `propSetStringN`). Values are keyframable and saved in the project. |
| Push buttons (Copy Params, Paste Params, Set Defaults, Reset Factory Defaults, Save Preset, Load Preset, Export LUT, Open User Manual, Calibrate to Stock) | Yes | A click sends `kOfxActionInstanceChanged` for that button to the instance in the host, without a time limit (a **Stop** button appears while it runs, in case the plug-in waits on a window of its own). Spektrafilm's buttons open no dialogs: they use the clipboard, its own preset and defaults files under `%APPDATA%\spektrafilm`, write a `.cube` beside its presets, or open the bundled manual. The values they set (`paramSetValue`, inside `paramEditBegin/End` for Paste, Load Preset and Reset) come back to Milan Pro and are written to the project as one undo step. |
| `paramGetValueAtTime` at the render time | Yes | Milan Pro sends the values at the frame being rendered. Other times read the same values. |
| `instanceChanged` with `kOfxChangeUserEdited` for the user's edits (it ignores `kOfxChangePluginEdited`) | Yes | Milan Pro sends instance changed (user edited) for each parameter whose value changed since the last frame, and for buttons. Values the plug-in sets itself (the HDR preset gang, printer lights, DIR stock calibration, the render-time ones) come back to Milan Pro with the frame and are stored in the project without an extra undo step. |
| `kOfxImageEffectPropRenderScale` | Sent correctly | Draft and Preview quality render smaller pictures: the render scale is the picture height over the full-quality height (an event's media height; the project height for track and output FX), and the render window, the region of definition and the clips' RoD are given in that scale and in canonical coordinates respectively. Spektrafilm does **not** read the render scale: it sizes its film grain, halation and diffusion from the source clip's RoD (`clipGetRegionOfDefinition`, canonical coordinates) against the picture it is given, so at Draft or Preview quality grain and halation can look coarser than in the full-quality render. |
| `kOfxImageEffectActionEndSequenceRender` and `PurgeCaches` free its GPU resources | Partly | End Sequence Render is sent when a sequence's render scale changes and when an instance is closed (at most 16 instances live per host). Purge Caches is never sent. |
| Message suite for errors (`kOfxMessageError`, ids `spektrafilmRenderer`, `spektrafilmDefaults`, `spektrafilmPreset`, `spektrafilmLutExport`, `spektrafilmUserManual`) | Yes | Messages are logged and shown in the FX window as the plug-in worded them ("Error: [spektrafilmRenderer] ..."), never as dialogs. A render error bypasses the plug-in with that text; a button's error only shows it. |

## What you should know

- **Input colour space.** Spektrafilm's default input colour space is **ARRI LogC4** (`inputColorSpace`, option 0 of 26; the RCM input defaults to DaVinci Intermediate). Milan Pro's frames are display-referred Rec.709/sRGB pictures (0 to 1). The FX window shows this once per plug-in when the choice is still at that default: "Milan Pro sends Rec.709 video; set Input Color Space to Rec.709 / sRGB". Set **Input Color Space** to **sRGB** or **Rec.709 Gamma 2.4** (whichever matches your footage) and keep the **Output Color Space** at Rec.709 Gamma 2.4 or sRGB. Milan Pro never changes the choice for you, because it does not implement OFX colour management; press OK on the hint to stop seeing it (kept in the preferences).
- **Milan Pro's presets and Spektrafilm's.** Both work: Spektrafilm's Save/Load Preset buttons use its own files; Milan Pro's FX window presets save every parameter too.
- **Values are 32-bit floats.** Milan Pro stores parameters as 32-bit floats, so an integer above 16,777,216 (a long random seed) is rounded; the plug-in is given the rounded value, so both sides agree.
- **Draft and Preview quality.** Grain and halation can look coarser in the preview than in the full-quality render (see the render scale row). The render itself runs at full size.
- **Speed.** Every frame goes through shared memory to the plug-in host and back as 32-bit float. `docs/PERFORMANCE.md` has the measured round-trip cost at 1080p, on top of Spektrafilm's own GPU time.
- **If it fails**, Milan Pro bypasses Spektrafilm for the rest of the session, says why in the status bar and the FX window (with a red "!" badge on the event's fx button), and keeps your settings. Fix the cause (for example a GPU driver), then press **Rescan** in View > Window > Plug-In Manager.

## Installing

Run Spektrafilm's own installer (`install.bat` copies the bundles to `C:\Program Files\Common Files\OFX\Plugins`), then start Milan Pro or press **Rescan** in the Plug-In Manager. Spektrafilm appears in the Video FX window under its grouping.
