# Format support

What Milan Pro reads and writes, and how that is known. Everything below is generated by ignored tests from files
FFmpeg makes from its lavfi sources (nothing recorded, nothing downloaded); do not edit the tables by hand, run
`tools/make-test-media.ps1` (decode, capability and camera tables) and `render_templates_e2e` (render table).

## Decode

Milan Pro reads media through the bundled FFmpeg. At first run it asks that FFmpeg what it can demux, decode, encode
and mux (`ffmpeg -demuxers -decoders -encoders -muxers -pix_fmts -filters`, cached per FFmpeg version) and applies its
own rules on top. A file whose codec this FFmpeg cannot decode imports as an offline item that says why, never as a
picture decoded as something else. Media Properties shows the verdict for each item: decode (software or hardware),
whether a video proxy can be made, and which render templates write the same format.

## Stills and image sequences

A numbered still (`shot_0001.png`, `shot_0002.png`, ...) picked or dropped asks "Open still image sequence" as VEGAS's
Open dialog does; checked, the run from its lowest number up to the first gap becomes one video item at the project's
frame rate (FFmpeg's image2 demuxer), its first file named in Project Media. Animated GIF, WebP and APNG import as
video. PNG (with alpha), JPEG, TIFF (8 and 16-bit), BMP, WebP, TGA, DPX, JPEG 2000, PSD (flattened, FFmpeg's decoder),
OpenEXR and Radiance HDR import as stills. OpenEXR is shown with a simple sRGB transfer (linear light, values above 1.0
clip) and Radiance HDR is tone-mapped first, until R40b's float pipeline. SVG needs an FFmpeg built with librsvg; the
bundled build has none, so an SVG imports offline with that reason. JPEG XL decodes when the build has libjxl. Render
As writes PNG, TIFF, OpenEXR and DPX sequences (below).

## HDR sources

Media Properties shows bit depth, colour space, transfer, primaries, matrix and the HDR10 mastering display and
content light level of each source; Project Properties › Video lists the project's HDR and wide-gamut media and holds
the Color management choice. PQ and HLG sources reach the 8-bit Rec.709 timeline through a view transform in the
decode filter (zimg): HDR reference white (203 cd/m², ITU-R BT.2408) becomes SDR white and highlights roll off with the
Möbius curve up to the mastering peak (or are clipped, as chosen); BT.2020 SDR sources are converted to Rec.709. The
preview, thumbnails, proxies and every render decode through the same filter, so they agree. SDR sources get no
transform and decode bit-identically to before. `hdr_view_transform_e2e` checks PQ and HLG clips against FFmpeg's own
tone map of the same file and against the SDR original. HDR output (an HDR timeline and HDR render) is R40b.

## Camera formats

Camera cards and folders are imported with File › Import › Camera Card Folder (or dropped as a folder). Checked on
FFmpeg-made stand-ins in `camera_formats_e2e` (MXF OP1a with XDCAM HD422, DNxHD and AVC-Intra; MXF OP-Atom; MOV with a
timecode track; an AVCHD card with a spanned pair); no camera originals were available.

AMF) are not offered yet: R22 detects them.
